# OpenChainBench — Animated Bench Video Spec (Remotion)

Generated by deepthink agent, 2026-06-04. Source of truth for the bench-data video implementation that comes after the intro POC.

## Target

- 20 s MP4, 1920×1080, 30 fps (600 frames)
- Twitter-shareable
- Per-bench, per-view-type (5 variants)
- Rendered on Remotion Lambda

## Global timeline (shared across all 5 views)

| Phase | Frames | Seconds | Purpose |
|---|---|---|---|
| Intro (3D logo) | 0–90 | 0–3 s | Brand stamp |
| Chart entrance | 90–150 | 3–5 s | Title + axes draw in |
| Race / reveal | 150–510 | 5–17 s | Animated data, the wow moment |
| Outro / CTA | 510–600 | 17–20 s | URL + share prompt |

Stage canvas: 1920×1080, paper background `#FAF7F2`, ink `#1C1A17`. Safe zone: 96 px outer margin. Bottom 60 px reserved for wordmark + URL strip.

## Shared header band (frames 90–510)

- Title (serif, 56 px, ink): bench name top-left at (96, 96)
- Metric subtitle (sans, 22 px, ink-muted, uppercase tracking 0.18 em) directly under: `<metric> — last 24 hours`
- LiveDot pulse (12 px) inline with subtitle
- Date tick (top-right, sans tabular 18 px): `YYYY-MM-DD — openchainbench.com`
- Footer strip frames 510–600 only: wordmark left, full URL right, share-prompt center

## Shared per-provider chrome

- `ProviderLogo` rendered as 56 px chip (4× site size) with brand color resolved via `buildProviderColors`
- Fallback chip uses initials + chipBackground
- Logos pre-rasterized server-side; passed in as base64 PNG to avoid Lambda font/CORS hell

## Shared easing

- Spring `{ damping: 18, stiffness: 110, mass: 0.9 }` for entrance
- `Easing.out(Easing.cubic)` for value interpolation
- `Easing.inOut(Easing.cubic)` for the rank swaps

## Shared input interface

```ts
type BenchVideoInput = {
  bench: { slug: string; name: string; metric: string; unit: string; higherIsBetter: boolean };
  viewType: "ranked-bar" | "time-series" | "distribution" | "donut" | "count";
  providers: {
    slug: string;
    name: string;
```

## 1. Ranked Bar — "Photo-finish leaderboard"

Approach: bars enter from the left in a randomized scrambled order, then re-sort to final ranks with FLIP-style animation. Winner bar gets a 200 ms gold flash + #1 badge stamp.

**A. Motion**: each bar grows out from the left edge at a uniform rate that ends at a wrong, scrambled width; at ~9 s a snap-sort phase reorders rows by p50, swapping vertical positions with cubic-inout. Final 1 s adds a #1 stamp slide-in and a brief value count-up on every row's right-side number.

**B. Pacing**: 360 frames for the race phase. Bars enter on a stagger of 6 frames each (max 20 providers = 120 frames stagger). Snap-sort happens at frame 360, lasts 30 frames. Count-up at 400–440. Winner flash 440–460. Wow moment: the sort swap at ~13 s.

**C. Composition** 1920×1080: title block top 240 px; chart body uses x: 200–1820 (1620 wide), y: 280–980. Per row height = `min(56, 700 / N)`. Provider logo (40 px) + name (28 px serif) in left 360 px column. Bar track starts at x: 580. Value label (sans tabular 24 px) right-aligned at x: 1820.

**D. Edges**: >20 providers → clip to top 16, render "+N more" pill at bottom. Lower-is-better → sort ascending, label leader as fastest, keep same visual. Mostly-flat data → widen visual range by remapping to [0.25, 1] of the bar so differences read. Missing data → excluded from race, never animated. Log-scale path inherits from the live chart's `useLog` test.

**E. Branding**: per-bar fill = `buildProviderColors` color; Okabe-Ito unused (palette in `series-colors.ts` already covers fallback). #1 stamp uses leader's brand color border + ink fill.

**F. Constants**: bar height 48 px, gap 8 px, font serif 28 px name, sans 24 px tabular value. Spring `{ damping: 22, stiffness: 140 }` on snap-sort. Bar grow uses `interpolate(frame, [enter, enter+30], [0, finalW], { extrapolateRight: 'clamp', easing: Easing.out(Easing.cubic) })`.

**G. Deliverable**: `views/RankedBarRace.tsx`. Timeline: 90–150 axes; 150–330 scrambled growth; 330–360 hold; 360–390 snap-sort; 400–440 count-up; 440–460 winner flash; 460–510 hold.

## 2. Time Series — "Lines drawing forward in time"

Approach: x-axis represents real time; lines draw from −24 h to now at 18× real-time. The "leader" tag follows the front-most line, swapping labels when overtakes happen. Final 2 s zooms the y-axis to the last hour for a punchy close-up.

**A. Motion**: clip-path or `strokeDasharray` reveal advancing from left to right. Trailing dot at the draw head pulses (reuse `ts-draw` aesthetic). A floating "LEADER" pill snaps between provider names whenever the front line changes. End of race: y-axis lo/hi animates from full-window to last-hour bounds (1 s ease-inout).

**B. Pacing**: 24 h compressed into 360 frames = 4 min/frame. Wow moment is the leader-swap, so the input pipeline must detect leader-change frames and the comp must add a 12-frame highlight burst on each. Min 1 swap; if data has none, skip the pill and rely on the y-zoom close-up.

**C. Composition**: title 96–200, chart 96–1820 by 240–940, footer strip 940–1020. Provider end-of-line label (sans 22 px) on right gutter; live pulse dot (8 px) at the draw head. Y-axis ticks left of 240 px, x-axis ticks below 940.

**D. Edges**: >12 lines → keep top 8 by mean-recent, render rest as `+N` ghost lines at 0.15 opacity. Gap handling: reuse the production `isGap` rule (zero among positives = break). Lower-is-better → flip the "LEADER" selection to min, no visual change. Mostly-flat → same y-zoom close-up at the end works; if literal flat, render the value as a single horizontal line with a wobble accent (1 px noise).

**E. Branding**: line stroke 3 px (vs 1.4 on site — thicker for video legibility), fill gradient as on site but stopOpacity 0.18 → 0. Leader pill background = leader brand color, text = `chipTextColor`.

**F. Constants**: line `strokeWidth: 3`, label font 22 px sans bold, leader pill 14 px sans uppercase tracking 0.14 em. Easing for draw: linear (real-time feel). Easing for y-zoom close-up: `Easing.inOut(Easing.cubic)` over 30 frames.

**G. Deliverable**: `views/TimeSeriesRace.tsx`. Timeline: 90–150 axes draw; 150–510 line race (360 frames); 480–510 y-zoom close-up overlaps last 30 frames; leader-pill bursts at swap frames.

## 3. Distribution — "Whisker reveal, ranked snap"

> Removed in v27 (2026-10-21): the review round marked it KO ("un peu bizarre, on peut retirer ce format"). The composition, the view id and the export option are gone; this section is kept as history.

Approach: rows stack in scrambled order; each row's p99 marker fires first as a vertical bar slamming in from the right edge, then p90 ring lands, then p50 dot pops with a small overshoot. After all rows complete, the table snap-sorts by p50.

**A. Motion**: per row, a 24-frame sequence — p99 slam (8 f), p90 ring fade-in (8 f), p50 pop with 1.15 overshoot then settle (8 f). Spread band (low-opacity p50–p99 fill) lerps in width during p99→p50 reveal. Final snap-sort uses same FLIP as ranked-bar.

**B. Pacing**: 360 frames available. With 12 providers and 4-frame row stagger, total reveal = 12×4 + 24 = 72 frames; pad with 60 f hold for read time; snap-sort 30 f; winner emphasis 30 f (zoom row to 1.05 scale).

**C. Composition**: title row top 240; rows fill 280–940. Row height `min(60, 660 / N)`. Logo+name left 380 px column right-aligned (matches site). Track from x: 460 to x: 1700. p50/p99 numeric columns at x: 1740/1820, sans tabular 22 px.

**D. Edges**: >18 rows → drop to top 12 by p50, badge `+N` ghost row. Lower-is-better → reuse site sort (ascending by p50). Mostly-flat distributions (p50 ≈ p99) → widen the field-max to `max(p99) * 1.4` so single-point rows still occupy visible track; spread band stays thin which is honest. Missing percentile → render p50 only, suppress whisker.

**E. Branding**: marker fill = provider color; spread band same color at 0.22 opacity. Ring stroke = color, 2.5 px (thicker than site's 1.5 px for video).

**F. Constants**: p50 dot 18 px, p90 ring 14 px stroke 2.5, p99 bar 4 px wide × 22 px tall. Overshoot spring `{ damping: 12, stiffness: 200 }`. Snap-sort same as ranked-bar.

**G. Deliverable**: `views/DistributionRace.tsx`. Timeline: 90–150 axes; 150–(150 + 4×N + 24) per-row reveals; +60 hold; 30 sort; 30 winner zoom; rest hold to 510.

## 4. Donut — "Slices fan out, then leader spotlight"

Approach: ring starts collapsed to a 1 px line at 12 o'clock; slices sweep open in p50-descending order like a fan opening. After full fan, hovered-leader simulation kicks in: every slice in turn (1 s each, 3 max) gets the centre-label spotlight cycling through top 3.

**A. Motion**: each slice's `a1` angle animates from `a0` to its target with a 200 ms ease-out, sequential not overlapping (chain reaction). Inner ring centre text crossfades on each spotlight swap. Subtle 1° rotation of the whole ring during the spotlight phase (gives a turntable feel).

**B. Pacing**: fan-out lasts 240 frames (slowest, deliberate). Spotlight cycle 240–450 (3 × ~70 frames). Wow moment: a dominant slice (>40 %) snapping wide.

**C. Composition**: title top 240; ring centered at (760, 600) with rOuter = 320, rInner = 220 (much larger than site's 92/68 since we have screen real estate). Legend list on right side, x: 1140–1820, two columns. Legend rows: chip 14 px + logo 28 px + name 24 px sans + percent 22 px tabular.

**D. Edges**: >16 slices → cap legend at 12, ring still draws every slice but groups tail as "Other" slice with neutral ink-muted fill at 0.4 opacity. Lower-is-better → "Leader" label resolves via `rankResults(higherIsBetter)` not biggest slice (mirror site bug-fix in donut-chart.tsx line 96). 100 % single provider → reuse site's full-ring two-arc path. Missing data → omitted, denominator recomputed.

**E. Branding**: slice fill = provider color at 1.0 opacity; 4 px paper-colored stroke between slices for separation (thicker than site's 2 px for video). Spotlight halo = drop-shadow filter colored with the slice's color at 0.4.

**F. Constants**: ring 320/220, stroke 4 px paper, centre label name 44 px sans semibold, value 26 px mono, "LEADER" eyebrow 18 px sans tracking 0.18 em uppercase. Sweep easing: `Easing.out(Easing.quad)`.

**G. Deliverable**: `views/DonutRace.tsx`. Timeline: 90–150 ring scaffold; 150–390 sequential fan-out; 390–510 leader spotlight cycle (top 3, ~40 f each); centre crossfade 12 f per swap.

## 5. Count Leaderboard — "Podium climb + receipt"

Approach: bars grow upward as vertical columns (not horizontal as the site does — vertical reads better at 1080p with few rows). Top 3 land on a 3-step podium with positions popping in order 3rd, 2nd, 1st (drumroll). Below podium, a "receipt" of remaining ranks scrolls in line by line.

**A. Motion**: top 3 bars grow from baseline to their podium height with overshoot springs (1.08 scaleY then settle). Ranks reveal in order: 3rd lands at frame 180 (1 s after axes), 2nd at 240, 1st at 330 (drumroll pause). Each landing fires confetti burst of 14 brand-color particles (40 f life, gravity, fade out). After podium, receipt rows 4..N slide in from right, 8 f stagger, mono font.

**B. Pacing**: 360 frames available. Bronze 150–180, silver 210–240, gold 270–330 (60 f anticipation pause before #1), confetti per landing 30 f overlap. Receipt 330–450, 8 f per row. 60 f hold. Wow moment: gold landing + confetti.

**C. Composition**: title top 240. Podium baseline at y=840, bars between 280 and 840. Bar width 200 px each, gap 60 px, centered around x=960. Provider logo 88 px above each bar; rank numeral 84 px serif under each podium step; metric value 32 px sans tabular at bar top. Receipt rows fill 880–1020 horizontally, sans 18 px.

**D. Edges**: <3 providers → downgrade to a 2-bar or 1-bar layout, skip receipt. Higher-is-better is the default for count benches (coverage); lower-is-better path supported by reversed rank order, same visual. Tied leaders → render side-by-side at same height with shared confetti burst. Mostly-flat → exaggerate by remapping bars to start from y=400 not baseline (visual lie warning — add tiny "scale clipped" note at 14 px ink-faint).

**E. Branding**: bar fill = provider color, with a subtle linear gradient (top 100 %, bottom 85 %) for depth. Confetti particles = brand color array. Podium step base = ink-soft fill (`#7a7166`) so brand colors pop against it.

**F. Constants**: bar 200×600 max, podium step heights 200/120/80 (gold/silver/bronze), numeral serif 84 px, logo 88 px, confetti particles 14 per landing with random initial velocity in [−12, 12] x and [−22, −8] y, gravity 0.6 px/f².

**G. Deliverable**: `views/CountPodium.tsx`. Timeline: 90–150 podium drawing; 150–180 bronze; 210–240 silver; 270–330 gold (with anticipation hold 240–270); confetti overlays; 330–450 receipt scroll-in; 450–510 hold.

## Render notes (apply to all 5)

- All views consume the same `BenchVideoInput`; differing fields gated by `viewType`
- Pre-bake `logoPng` at site build time; Remotion Lambda has flaky SVG/font fallback otherwise
- `<ChartFrame>` wraps every view and renders title/footer; views only paint the inner canvas
- For Twitter spec: H.264 yuv420p, ~12 Mbps, AAC silent track, 1080p30; file 30–40 MB
- File naming for Lambda output: `bench-<slug>-<viewType>-<YYYYMMDD>.mp4`
- Intro3D and Outro live outside view files — one shared component each, drive their own 90-frame animations against a `getInputProps()` brand object
- Spring presets centralized in `lib/motion.ts`: `RACE_SPRING`, `OVERSHOOT_SPRING`, `SNAP_SPRING`
- For preview iteration: build a `<BenchVideo>` story per view in Remotion Studio loading fixture JSON from `/fixtures/<viewType>.json` snapshotted from a live bench API call
